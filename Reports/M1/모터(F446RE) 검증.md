# M1-④ Node 2 (F446RE) — TIM3 PWM 모터 단독 회전 검증

> 전제: M0 완료(LD2 블링크 + printf VCP 출력). 부품은 있으나 미배선.
> 이번 단계 목표: **RTOS 없이, CAN 없이, 센서 없이** 모터만 정확히 20 kHz PWM으로 돌린다.

---

## 0. 이번 단계에서 확정되는 것

M1-④는 "바퀴가 돌았다"로 끝나면 손해다. 여기서 확정해 두면 뒤가 편한 값이 3개 있다.

| 확정할 값 | 어디서 쓰이나 |
|---|---|
| **PCLK1 = 40 MHz / TIM3 = 80 MHz** | M2 CAN 비트타이밍(Prescaler 5, tq 8 MHz)이 이 값에 전적으로 의존 |
| **최소 기동 듀티** (Phase 5 실측) | M4 데드존 ±8%, 슬루레이트 제한의 근거 |
| **COAST vs BRAKE 정지거리** | M6 "정지 거리 < 20 cm" 측정, M5 긴급제동 방식 선택 |

그래서 **클럭 설정을 M2로 미루지 말고 지금 160 MHz로 확정**하는 것을 권한다.
지금 기본 클럭(HSI 16 MHz)으로 대충 맞춰 놓으면 M2에서 클럭을 바꾸는 순간 PWM 주파수가 통째로 틀어져 이 검증을 다시 해야 한다.

### 0-1. 실측 확정값 (2026-08-23)

| 항목 | 실측값 | 비고 |
|---|---|---|
| 배터리 전압 (18650 ×2, 만충 무부하) | **8.1 V** | 측정 시 배터리 상태 기록용 |
| L298N High-side 강하 | 0.90 V | VMS − OUT1 |

| 배선 손실 (전원측 / 출력측) | 0.0 V / 0.0 V | 브레드보드 경유 없음 확인 |

> `motor.h`의 `MOTOR_MIN_MOVE_PCT = 33` 으로 갱신 완료.

## 1. 배선

### 1-1. 배선표 (회로도 Rev 0.1 기준)

| L298N | MCU 핀 | 보드 위치 | 역할 |
|---|---|---|---|
| **ENA** | PA6 | CN10-13 (D12) | TIM3_CH1 PWM 20 kHz — 좌 |
| **IN1** | PB12 | CN10-16 | 좌 방향 A |
| **IN2** | PB13 | CN10-30 | 좌 방향 B |
| **IN3** | PB14 | CN10-28 | 우 방향 A |
| **IN4** | PB15 | CN10-26 | 우 방향 B |
| **ENB** | PA7 | CN10-15 (D11) | TIM3_CH2 PWM 20 kHz — 우 |
| **GND** | GND | CN7-8 / CN7-20 | ★ 공통 접지 |
| 12V(VMS) | — | — | 18650 ×2 (7.4 V) **직결** |
| OUT1/OUT2 | — | — | 좌측 모터 |
| OUT3/OUT4 | — | — | 우측 모터 |
| 5V | — | — | **연결하지 않음** (아래 참조) |

### 1-2. 배선 전에 반드시 확인할 5가지

1. **ENA / ENB 점퍼 캡을 뽑는다.**
   L298N 모듈은 공장 출하 시 ENA·ENB가 점퍼로 5 V에 물려 있다. 안 뽑으면 PWM이 무시되고 모터가 항상 100 %로 돈다. **이게 이 단계에서 가장 흔한 실패다.**

2. **5V-EN 점퍼는 그대로 둔다 (VMS 7.4 V이므로).**
   모듈의 78M05가 7.4 V에서 5 V 로직 전원을 만들어 준다. 이 점퍼를 꽂아 둔 상태에서 **L298N의 5V 핀을 NUCLEO 5V에 연결하면 두 레귤레이터 출력이 충돌**한다. 회로도에서 L298N 5V 핀이 X(미연결)로 되어 있는 이유다. HC-SR04는 나중에 NUCLEO의 5V에서 따로 받는다.

3. **공통 접지 — 이 단계 최대의 함정.**
   L298N GND ↔ NUCLEO GND를 굵은 선으로 연결. 이게 없거나 **헐거우면** 방향핀 레벨이 뜨고 모터가 제멋대로 돈다.

   ⚠️ **나사 단자 하나에 굵기가 다른 두 선(18650 홀더 전선 + 듀폰 점퍼선)을 같이 물리지 말 것.** 압착판이 단단한 쪽만 물어서 연선이 계속 빠진다. 실제로 이것 때문에 최소 기동 듀티가 33% → 75%로 잘못 측정되는 사고가 있었다(§6 참조).

   올바른 방법:
   - **Y 분기 납땜(권장):** L298N 단자에서 2~3 cm 이내 지점의 18650 검정선 피복을 벗기고 NUCLEO GND용 전선을 납땜 분기. **나사 단자에는 선 하나만 들어간다.**
   - **분기점은 L298N에 가까울수록 좋다.** 모터 귀환 전류(약 1A)가 검정선에 I×R 강하를 만들기 때문에, 배터리 쪽에서 따면 NUCLEO 기준 전위가 L298N 기준 전위와 어긋난다. 3.3V 로직에서 L298 High 문턱 2.3V까지 마진이 1.0V뿐이라 0.3V 어긋남도 치명적이다.
   - 부품을 살 수 있으면 **WAGO 221-413 레버 커넥터**를 접지 스타 포인트로 쓰는 것이 가장 깔끔하다. CAN 트랜시버 GND, HC-SR04 GND가 추가될 것을 감안하면 5구(221-415)도 좋다.
   - 결선 후 **NUCLEO GND 핀 ↔ L298N GND 나사단자 도통 확인(0.5Ω 이하)** 및 **양쪽 선 텐션 테스트** 필수.

4. **모터 노이즈 대책을 지금 해 둔다.** (나중에 하면 원인 추적이 지옥이 된다)
   - 모터마다 0.1 µF 세라믹 3개: 단자↔단자 1개, 각 단자↔모터 케이스 1개씩
   - L298N 12V ↔ GND에 470 µF 전해 커패시터 (회로도 C1)
   - 모터 배선은 두 가닥을 꼬아서(twisted pair) 배치

   > **커패시터가 저듀티 문제의 원인은 아니다.** 벌크 커패시터 부재는 전류가 많이 흐르는 **고듀티**에서 증상이 나타나므로, "저듀티에서만 안 돈다"는 증상과는 인과가 반대다. 커패시터는 §5 DoD의 **"1분 연속 구동 시 리셋 0회"** 항목과 M4 슬루레이트 구간을 위한 것이다.

5. **첫 통전 시 바퀴를 공중에 띄운다.** 섀시를 책·컵 위에 올려 바퀴가 바닥에 닿지 않게. 방향이 반대로 나가는 건 흔한 일이다.

> **3.3 V로 L298N을 구동해도 되나?**
> 된다. L298의 입력 High 문턱은 2.3 V이므로 3.3 V GPIO로 충분하다. 다만 마진이 크지 않으므로 배선을 짧게 하고, 만약 동작이 불안정하면 이 항목과 §1-2 3번(접지)을 의심할 것.

## 2. CubeMX 설정

### 2-1. RCC

| 항목 | 값 |
|---|---|
| High Speed Clock (HSE) | **BYPASS Clock Source** ← "Crystal/Ceramic" 아님 |
| Low Speed Clock (LSE) | **Disable** (F446RE에 32.768 kHz 크리스털 미실장) |

> ⚠️ 두 항목 모두 실수로 Crystal / Enable 상태가 되기 쉽다. NUCLEO-F446RE에는 **HSE 크리스털도 LSE 크리스털도 실장되어 있지 않다.** 잘못 두면 `HAL_RCC_OscConfig()`가 타임아웃 후 `Error_Handler()` 무한루프에 빠지고, 보드는 플래시는 되는데 아무것도 안 움직이는 상태가 된다.
>
> 구분법: **Pinout 화면에서 PH0만 `RCC_OSC_IN`으로 잡혀 있으면 BYPASS**, PH0/PH1이 **둘 다** 잡혀 있으면 Crystal 모드다. PC14/PC15가 `RCC_OSC32_*`로 잡혀 있으면 LSE가 켜져 있는 것이다.
>
> IWDG(M5)는 LSI 32 kHz로 돌기 때문에 LSE를 꺼도 아무 영향이 없다.

### 2-2. Clock Configuration

| 항목 | 값 | 결과 |
|---|---|---|
| Input frequency | 8 MHz | ST-LINK MCO |
| PLL Source Mux | HSE | |
| **/M** | **4** | VCO 입력 2 MHz (ST 권장치) |
| **×N** | **160** | VCO 320 MHz |
| **/P** | **2** | **SYSCLK 160 MHz** |
| /Q | 7 | USB 미사용, 무관 |
| AHB Prescaler | /1 | HCLK 160 MHz |
| **APB1 Prescaler** | **/4** | **PCLK1 40 MHz → APB1 Timer 80 MHz** |
| APB2 Prescaler | /2 | PCLK2 80 MHz |

> **M=8 / N=320 도 결과는 같은 160 MHz지만, 그 경우 VCO 입력이 1 MHz로 허용 범위(1~2 MHz)의 하한에 걸린다.** ST는 지터를 줄이기 위해 2 MHz를 권장하므로 **M=4 / N=160** 을 쓴다. TIM3 설정과 CAN Prescaler는 결과 주파수가 동일하므로 손댈 필요 없다.
>
> APB1 프리스케일러가 1이 아니므로 **APB1 타이머 클럭은 PCLK1의 2배(80 MHz)** 가 된다.
> CubeMX Clock Configuration 화면의 "APB1 timer clocks" 칸에 **80 MHz**가 떠 있는지 눈으로 확인할 것. 이 값이 PWM 계산의 입력이다.
>
> Flash Latency는 CubeMX가 자동으로 **5 WS**로 잡는다(150 < HCLK ≤ 180).

### 2-3. TIM3

**Mode**
- Clock Source: `Internal Clock`
- Channel1: `PWM Generation CH1`
- Channel2: `PWM Generation CH2`

**Parameter Settings**

| 항목 | 값 |
|---|---|
| Prescaler (PSC) | **0** |
| Counter Mode | Up |
| Counter Period (ARR) | **3999** |
| Internal Clock Division | No Division |
| auto-reload preload | **Enable** |
| PWM Generation Ch1/Ch2 — Mode | PWM mode 1 |
| Pulse | 0 |
| Output compare preload | **Enable** |
| Fast Mode | Disable |
| CH Polarity | High |

**검산**

```
TIM3 clk = PCLK1 × 2 = 40 MHz × 2 = 80 MHz
f_PWM    = 80 MHz / ((PSC+1) × (ARR+1))
         = 80 MHz / (1 × 4000)
         = 20 000 Hz            ← 주기 50 µs, 정확히 20 kHz
분해능    = 4000 step = 0.025 %/step
CCR      = 4000 × duty / 100    (duty 100% → CCR 4000 > ARR 3999 → 항상 High)
```

> **주파수를 임시로 낮추는 법(디버깅용):** `PSC`만 `0 → 19`로 바꾸면 80 MHz / (20 × 4000) = **1 kHz**가 된다. ARR이 그대로라 CCR 계산식을 손댈 필요가 없다. "L298N이 20 kHz를 못 따라가는가"를 가릴 때 이 한 줄만 바꿔 비교하면 된다.
> (2026-08-23 검증 결과: **20 kHz에서 최소 기동 듀티 33%**로 정상. 주파수 낮출 필요 없음.)

> ⚠ **핀 확인:** TIM3_CH2는 PA7 / PB5 / PC7에 배치될 수 있다. CubeMX가 PC7을 잡아 버리면
> M1-⑤ HC-SR04 TRIG(PC7)와 충돌한다. Pinout 화면에서 **PA6 = TIM3_CH1, PA7 = TIM3_CH2**인지
> 직접 확인하고, 아니면 해당 핀을 Ctrl+클릭해서 강제 배치할 것.

### 2-4. GPIO

| 핀 | 모드 | 설정 | User Label |
|---|---|---|---|
| PB12 | GPIO_Output | Push Pull / No pull / Low / **초기값 Low** | `MOT_IN1` |
| PB13 | GPIO_Output | 동일 | `MOT_IN2` |
| PB14 | GPIO_Output | 동일 | `MOT_IN3` |
| PB15 | GPIO_Output | 동일 | `MOT_IN4` |
| PA5 | GPIO_Output | (M0에서 설정됨) | `LD2` |
| PC13 | **GPIO_Input** | Pull-up | `B1` |

- User Label을 위 이름 그대로 넣으면 `main.h`에 `MOT_IN1_Pin` 등이 생성되어 `motor.c`가 그대로 컴파일된다. 라벨을 안 붙여도 `motor.c` 안의 폴백 정의가 받아 준다.
- **PC13(B1)은 EXTI가 아니라 GPIO_Input으로** 설정한다. 이번 테스트는 폴링으로 읽는다. 버튼을 누르면 PC13이 GND로 떨어지므로 **눌림 = `GPIO_PIN_RESET`** 이다.
- ⚠️ **CubeMX 재설정 중 User Label이 유실되는 사고가 잦다.** PC13이 `[BUTTON]`, PA5가 `[LD1]`로 보이면 라벨이 보드 기본값으로 되돌아간 것이고, `B1_Pin` / `LD2_Pin` 을 쓰는 코드가 전부 깨진다. 라벨을 다시 넣거나, `main.h`의 USER CODE 구간에 폴백을 둔다.

```c
/* USER CODE BEGIN Private defines */
#ifndef B1_Pin
  #define B1_Pin         BUTTON_Pin
  #define B1_GPIO_Port   BUTTON_GPIO_Port
#endif
#ifndef LD2_Pin
  #define LD2_Pin        LD1_Pin
  #define LD2_GPIO_Port  LD1_GPIO_Port
#endif
/* USER CODE END Private defines */
```

## 3. 코드 통합

첨부 파일 4개를 프로젝트에 넣는다.

```
Core/Inc/motor.h            ← 모터 드라이버 헤더
Core/Inc/motor_test.h       ← 검증 시퀀스 헤더
Core/Src/motor.c            ← 모터 드라이버 구현
Core/Src/motor_test.c       ← 검증 시퀀스 구현
```

`main.c`에는 `main_usercode_snippets.c`의 [1]~[4] 블록을 **USER CODE 주석 사이에** 붙여넣는다.
(이 파일 자체는 프로젝트에 추가하지 말 것 — 참고용 스니펫 모음이다.)

### 설계 의도

`motor.c`는 M1에서 버리는 코드가 아니다. **M4 차동 구동, M5 Fail-safe에서 MotorTask가 그대로 이 API만 호출**하도록 만들었다.

- `Motor_Set(id, pct)` — `pct`는 -100~+100. CAN 프레임 `throttle`/`steering`의 타입(int8)과 일치시켰다.
- `Motor_Stop(mode)` — LINK_LOST / E-BRAKE / FAULT가 모두 이 한 함수로 수렴한다. 계획서 §2-1의 "모든 실패 경로가 정지로 수렴" 구조를 함수 레벨에서 강제하는 것.
- `Motor_GetDuty()` — 텔레메트리 `0x200` byte 2/3에 그대로 실린다.
- PWM 레지스터에 쓰는 곳은 `motor_write_duty()` **한 군데뿐**이다. M3에서 경쟁 상태를 찾을 때 여기만 보면 된다.

`motor_test.c`는 M1 전용이다. HAL_Delay를 쓰므로 **M3 RTOS 통합 시 프로젝트에서 제외**한다.

### 3-1. 최소 기동 듀티 반영 (M4 예고)

최소 기동 듀티가 33%라는 것은, **명령값 1~32%가 전부 "안 도는 구간"** 이라는 뜻이다. 조이스틱을 조금 밀었는데 아무 반응이 없다가 갑자기 튀어나가면 제어감이 최악이 된다. M4에서 명령값을 다음처럼 재매핑해야 한다.

```c
/* |cmd| 1~100 → MOTOR_MIN_MOVE_PCT ~ 100 으로 선형 재매핑 */
if (mag == 0) duty = 0;
else          duty = MOTOR_MIN_MOVE_PCT
                   + (100 - MOTOR_MIN_MOVE_PCT) * mag / 100;
```

이렇게 하면 사용 가능한 제어 해상도가 67 스텝으로 줄어들지만, 명령-반응이 단조롭게 이어진다. 계획서 §7.1의 N1(조향 선형성) 판정 기준도 이 매핑을 전제로 본다.

## 4. 검증 절차

### Step 1 — 모터 없이 파형부터 (Phase 0)

L298N을 아직 연결하지 않은 상태. 보드만 USB로 연결하고 플래시 → B1(파란 버튼) 누름.

**멀티미터(DC 전압)로 PA6 ↔ GND 측정:**

| 코드가 출력하는 듀티 | 기대 평균 전압 | CCR |
|---|---|---|
| 0 % | 0.00 V | 0 |
| 25 % | 0.825 V | 1000 |
| 50 % | 1.650 V | 2000 |
| 75 % | 2.475 V | 3000 |
| 100 % | 3.30 V | 4000 |

PA7도 동일해야 한다. **±5 % 이내면 합격.**

오실로스코프나 로직 애널라이저가 있다면 **주기 50 µs**를 확인한다. 이 확인이 M2에서 CAN 비트폭 2 µs를 볼 때 쓸 장비 세팅 리허설도 된다.

UART 콘솔에 찍히는 `PCLK1 : 40000000 Hz`, `TIM3 : PSC=0 ARR=3999 -> 20000 Hz`도 함께 확인한다. 여기가 틀리면 배선을 아무리 봐도 소용없다.

### Step 2 — 모터 연결 (Phase 1~4)

전원을 모두 끄고 §1 배선을 완료한 뒤, **바퀴를 띄우고** 다시 B1.

| Phase | 확인 사항 |
|---|---|
| 1 | 좌측 바퀴만 **전진** 방향으로 매끄럽게 가속/감속. 우측은 정지 상태 유지 |
| 2 | 좌측 바퀴만 **후진**. Phase 1과 정확히 반대 방향 |
| 3 | 우측 바퀴 동일 |
| 4 | 양쪽 전진 → COAST 정지(서서히 멈춤) vs BRAKE 정지(즉시 멈춤) 차이가 체감될 것 |
| 4 | 제자리 회전 2방향 |

**모터 방향이 반대라면** 코드를 고치지 말고 **OUT1↔OUT2 선을 바꿔 끼운다.** 소프트웨어로 뒤집으면 나중에 회로도와 코드가 어긋나서 디버깅이 어려워진다.

### Step 2.5 — L298N 전압 강하 실측 (권장)

최소 기동 듀티가 예상(25~40%)보다 높게 나오면, **원인이 드라이버인지 배선인지 모터인지**를 이 측정 하나로 가른다.

**대원칙 3가지**

1. **100% 듀티에서 잰다.** PWM이 걸린 상태로 재면 "강하"가 아니라 "평균값"을 읽는다.
2. **모터를 연결하고 실제로 도는 상태에서 잰다.** 강하는 전류에 비례한다. 무부하로 재면 0에 가깝게 나와 오판한다.
3. **프로브를 L298N 나사 단자에 직접 댄다.** 브레드보드 레일에 대면 드라이버 강하와 배선 손실이 섞인다.

**100% 고정용 임시 코드** (측정 후 삭제)

```c
HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_1);
HAL_GPIO_WritePin(MOT_IN1_GPIO_Port, MOT_IN1_Pin, GPIO_PIN_SET);
HAL_GPIO_WritePin(MOT_IN2_GPIO_Port, MOT_IN2_Pin, GPIO_PIN_RESET);
__HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, 4000);  // CCR > ARR → 항상 High
```

이 상태에서 **OUT1이 High측, OUT2가 Low측**이 된다.

**측정: 검정 프로브를 L298N GND 나사 단자에 고정하고 빨간 프로브만 이동**

| # | 위치 | 2026-08-23 실측 |
|---|---|---|
| ① | 배터리 (+) 단자 | 8.1 V |
| ② | L298N VMS 나사 단자 | 8.1 V |
| ③ | L298N OUT1 나사 단자 | 7.2 V |
| ④ | 모터 (+) 리드선 | 7.2 V |
| ⑤ | L298N OUT2 나사 단자 | 0.75 V |
| ⑥ | 모터 (−) 리드선 | 0.75 V |

| 계산 | 식 | 실측 | 판정 |
|---|---|---|---|
| 전원측 배선 손실 | ① − ② | 0.0 V | 정상 (0.3V 넘으면 배선 문제) |
| 상단 강하 | ② − ③ | 0.90 V | 정상 |
| 하단 강하 | ⑤ | 0.75 V | 정상 |
| **L298N 총 강하** | (②−③) + ⑤ | **1.65 V** | 1A typ 1.8V 대비 양호 |
| 출력측 배선 손실 | (③−④) + (⑥−⑤) | 0.0 V | 정상 |
| **모터 실제 전압** | ④ − ⑥ | **6.45 V** | 충분 |

**판정 기준 (L298 데이터시트 기준)**

| 총 강하 | 판정 |
|---|---|
| 1A에서 1.8~2.5 V | 정상 |
| 2A에서 3.2~4.9 V | 정상 (상한 근처) |
| 0.5A 이하인데 3V 이상 | 비정상 — 칩 손상 또는 접촉 불량 |

전류를 함께 재면(멀티미터 10A 잭을 배터리 (−) ↔ L298N GND에 직렬, **5초 이내**) 판정이 정확해진다.

### Step 3 — 최소 기동 듀티 실측 (Phase 5)

5 %부터 1 %씩 올라간다. **바퀴가 처음으로 실제로 돌기 시작하는 듀티**를 좌/우 각각 기록한다.

- 보통 TT 기어드 모터 + L298N(7.4 V) 조합에서 **25~40 %** 사이에 나온다.
- 좌우 값이 10 % 이상 차이 나면 모터 개체차 또는 배선 저항 차이다. M4 차동 구동에서 직진 보정이 필요하다는 신호이므로 **반드시 메모해 둘 것.**
- 측정 후 `motor.h`의 `MOTOR_MIN_MOVE_PCT`를 실측값으로 갱신한다.

**2026-08-23 실측: 좌 33 % / 우 33 % (편차 0 %), 배터리 8.1 V, 20 kHz** → `MOTOR_MIN_MOVE_PCT = 33`

> **L298N 전압 강하 참고:** 실측 1.65 V(상단 0.90 + 하단 0.75). 18650 2직렬 8.1 V → 모터 단자 6.45 V. 3~6 V급 TT 모터에 적정하다. 배터리가 방전되어 6.5 V 아래로 떨어지면 최소 기동 듀티가 눈에 띄게 올라가므로, 측정 시 배터리 전압도 함께 기록해 둘 것.

## 7. 다음 단계

M1-④가 끝나면 남은 것은 **M1-⑤ HC-SR04 Input Capture 거리 측정(오차 ±2 cm)** 하나다.

M1-⑤ 예고 — 미리 정해 둘 것:
- ECHO(PB6) → TIM4_CH1, **1 kΩ + 2 kΩ 분압 필수** (5 V를 3.3 V로). 분압 없이 꽂으면 핀이 죽는다.
- TIM4는 APB1이므로 타이머 클럭이 역시 80 MHz. PSC = 79 → 1 MHz(1 µs/tick)로 잡으면 거리 계산이 `dist_cm = us / 58`로 깔끔해진다.
- `HAL_Delay` 폴링 금지 — Input Capture 인터럽트로 상승/하강 엣지를 잡는다.
- 30 ms 내 ECHO 미수신 시 타임아웃 → 255(측정 불가) 반환. M5 FAULT 판정의 입력이 된다.

두 개가 끝나면 **M2(클럭 & CAN)** — 계획서가 스스로 "여기서 막히면 프로젝트가 멈춘다"고 표시한 구간이다. 다행히 M1-④에서 클럭을 160 MHz/40 MHz로 이미 확정했으므로, M2에서는 CAN 타이밍만 보면 된다.
