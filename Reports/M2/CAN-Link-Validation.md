# M2 클럭 및 CAN 링크 검증 기록

기록일: 2026-11-07 (Asia/Seoul)

> 후속 확인 (2026-11-09): 차량을 RTOS로 이관한 [M3-2 시험](../M3/CAN-Queue-Integration.md)에서 Node 1의 `tx=3000 rx=3000` PASS와 차량의 큐 처리·응답 3,000회 PASS를 사용자 로그로 확보했다. 아래 본문은 2026-11-07 시험 당시의 기록을 유지한다. 후속 로그를 당시의 양 노드 베어메탈 시험 결과로 소급하지 않으며 CAN 비트폭·MCO 실측은 여전히 미완료다.

**Normal 모드에서 Node 2의 수신 검증 3,000회와 응답 송신 완료 3,000회를 확인했다.**
최종 Node 2 시험의 데이터 오류, HAL CAN 오류, Bus-Off와 타임아웃은 모두 0이었다.
Node 1의 최종 PASS 로그 재확인과 CAN 비트폭·MCO 주파수 실측은 남아 있다.
따라서 이 기록은 Node 2 기능 시험의 합격 기록이며, 계획서의 M2 전체 완료 선언은 아니다.

## 1. 근거와 판정 범위

사용자가 실제 보드에서 확인한 UART 출력과 디버거 값, 저항 측정 결과를 대화로 전달했다.
이 문서는 그 보고를 현행 소스와 대조해 작성했다. 작성 에이전트가 보드를 직접 조작하거나
계측한 결과는 아니다. 터미널 원본 파일과 계측 파형은 아직 첨부되지 않았다.

| 항목 | 판정 | 근거 |
|---|---|---|
| 두 보드의 Loopback 시험 | 사용자 정상 확인 | 양쪽 모두 약 70초 뒤 정상 출력 확인 보고. 노드별 원본 로그 미첨부 |
| 연결된 버스의 종단저항 | 정상 | 사용자 측정 약 60Ω. 모듈을 각각 측정했을 때는 120Ω |
| Node 2 CAN 시작 | 정상 | 디버거에서 `HAL_CAN_STATE_LISTENING`, `ErrorCode=0` 확인 |
| Node 2 Normal 수신 검증 | PASS | `rx=3000`, `bad=0` |
| Node 2 Normal 응답 송신 | PASS | `tx=3000`, `completed=3000`, `tx_fail=0` |
| Node 2 정상 시험 오류 감시 | 오류 관측 없음 | `errors=0`, `mask=0`, `bus_off=0`, `timeout=0` |
| Node 1 Normal 최종 수신 검증 | 재확인 필요 | 마지막에 Node 1 결과로 전달한 문자열은 Node 2 로그였다고 사용자가 정정 |
| CAN 비트폭 2µs | 미측정 | 500kbps 설정에서 계산한 기대값이며 실측하지 않음 |
| MCO 출력 주파수 | 미측정 | MSI 보정은 코드에 구현되어 있으나 주파수 계측은 수행하지 않음 |
| Bus-Off 감지 경로 | 구현, 강제 오류 시험 미수행 | 콜백은 구현됨. 정상 시험의 `bus_off=0`은 감지 경로 동작 검증이 아님 |

Node 2의 정상 수신과 송신 완료는 실제 버스의 통신 동작을 뒷받침한다.
다만 CAN 하드웨어 ACK와 Node 1 애플리케이션의 순번·내용 검증은 서로 다른 단계다.
Node 1의 최종 `rx=3000` 로그는 별도로 확보해야 한다.

## 2. 시험 구성

| 항목 | Node 1 | Node 2 |
|---|---|---|
| 보드 | NUCLEO-L432KC | NUCLEO-F446RE |
| 역할 | 20ms마다 시험 프레임 송신, 에코 검증 | 프레임 검증 후 같은 데이터를 에코 |
| 시스템 클럭 설정 | MSI 48MHz, LSE 자동 보정 | HSE Bypass 8MHz → PLL 160MHz |
| CAN 클럭 설정 | PCLK1 48MHz | PCLK1 40MHz |
| Prescaler | 6 | 5 |
| BS1 / BS2 / SJW | 13 / 2 / 2 TQ | 13 / 2 / 2 TQ |
| 계산 비트율 / 샘플 포인트 | 500kbps / 87.5% | 500kbps / 87.5% |
| CAN 모드 | Normal | Normal |
| RX 핀 | PA11, D10 | PA11, CN10-14 |
| TX 핀 | PA12, D2 | PA12, CN10-12 |
| 트랜시버 | SN65HVD230, 보드의 3.3V | SN65HVD230, 보드의 3.3V |
| 인터럽트 | RX0, SCE | RX0, SCE, TX |
| UART 설정 | 115200 baud, 8N1 | 115200 baud, 8N1 |

모듈의 CANH끼리, CANL끼리 연결하고 두 보드와 모듈은 공통 GND를 사용한다.
각 모듈은 해당 보드에서 전원을 공급받는다. 두 보드의 3.3V 출력끼리는 연결하지 않는다.
각 끝의 120Ω 종단저항 두 개가 병렬로 연결되어 버스 측정값은 약 60Ω이다.

디버깅 과정에서는 Node 2를 보조배터리에 연결한 구성과, Node 2를 노트북에 연결해
관찰하도록 전원을 바꾼 구성을 사용했다. 최종 PASS는 두 번째 구성을 안내한 뒤 보고됐다.
최종 시험 시점의 전원 배치 사진이나 명시적 재확인 기록은 없으므로 전원 구성별 합격을
별도로 주장하지 않는다. Node 2의 LD3 점등은 확인했으나 JP1 변경 이력은 확인되지 않았다.

## 3. 시험 프레임과 실행 조건

| 필드 | 값 |
|---|---|
| Node 1 → Node 2 ID | 표준 데이터 프레임 `0x100` |
| Node 2 → Node 1 ID | 표준 데이터 프레임 `0x200` |
| DLC | 8 |
| Byte 0~3 | 0~2999 순번, uint32 little-endian |
| Byte 4~7 | `55 AA 12 34` |
| 송신 횟수 / 주기 설정 | 3,000회 / 20ms |
| Node 1 시작 대기 / 마지막 응답 대기 | 2초 / 1초 |
| Node 2 완료 대기 | 마지막 수신 후 100ms |
| Node 2 실패 시간 조건 | 첫 수신 후 1초 무수신 또는 첫 수신부터 65초 초과 |

Node 2는 첫 프레임 이전에는 계속 기다린다. 3,000개를 수신하면 완료 대기 후 CAN을 정지한다.
Node 1도 시험이 끝나면 CAN을 정지한다. 다음 시험은 양쪽을 새로 시작해야 한다.
이 페이로드는 M2 전용이며 최종 차량 명령·상태 또는 CRC-8 형식이 아니다.

20ms × 3,000회는 약 60초의 송신 구간에 해당한다. Node 1 로그까지의 예상 시간은 약 63초다.
이 시간은 코드에서 계산한 값이며 정밀 시간 계측 결과가 아니다.
`slips=0`은 검사 문맥에서 송신 예정 시각보다 한 주기 이상 늦어진 사건이 없다는 뜻으로,
모든 프레임의 정확한 주기나 지터를 측정한 결과가 아니다. Node 2 Normal 모드는 자체 주기
송신을 하지 않으므로 Node 2의 `slips=0`만으로 Node 1 주기를 판정하지 않는다.

## 4. 최종 Node 2 결과

사용자가 전달한 성공 로그 원문:

```text
PASS: tx=3000 completed=3000 rx=3000 bad=0 tx_fail=0 slips=0 errors=0 mask=0x00000000 bus_off=0 timeout=0
```

| 카운터 | 결과 | 해석 |
|---|---:|---|
| `tx` | 3000 | 응답 메일박스 등록 성공 |
| `completed` | 3000 | HAL 송신 완료 콜백 기록 |
| `rx` | 3000 | 순번과 페이로드가 정상인 수신 |
| `bad` | 0 | 순번·헤더·내용 검사 오류 없음 |
| `tx_fail` | 0 | 메일박스 부족 또는 송신 등록 실패 없음 |
| `errors` / `mask` | 0 / 0x00000000 | HAL 오류 콜백 및 누적 오류 비트 없음 |
| `bus_off` / `timeout` | 0 / 0 | 해당 종료 원인 없음 |

`tx`만으로 전송 성공을 판정하지 않는다. `errors`는 HAL 콜백 횟수이며 물리 버스의
오류 프레임을 계측기로 센 횟수가 아니다.

Node 1의 현행 출력에는 `completed`와 `timeout`이 없다. 다음 문자열은 **향후 확인할
정상 출력 예시**이며, 이번 시험의 확보된 Node 1 실측 로그가 아니다.

```text
[M2] PASS: tx=3000 rx=3000 bad=0 tx_fail=0 slips=0 errors=0 mask=0x00000000 bus_off=0
```

## 5. 실패 기록과 조치

| 단계 | 관측 | 해석 및 조치 |
|---|---|---|
| 초기 Node 1 시험 | `tx=3`, `rx=0`, `tx_fail=2997`, `mask=0x23`, `bus_off=0` | ACK 오류·Error Warning·Error Passive 기록. 자동 재전송 중 메일박스 3개가 점유된 상태와 일치. 최초 ACK 부재의 단일 원인은 확정하지 않음 |
| 전원 확인 | Node 2 LD1 느린 점멸, LD3 빨간색 점등 | ST-LINK 표시와 MCU 전원 표시를 구분. LD3 점등만으로 펌웨어 실행을 확정하지 않음 |
| 배선 확인 | 개별 모듈 120Ω, 버스 연결 후 60Ω | 종단저항 정상. 추가 저항 불필요 |
| Node 2 초기화 확인 | `HAL_CAN_STATE_LISTENING`, `ErrorCode=0` | 관찰 당시 CAN 시작 성공 |
| 부분 수신 시험 | 송신 및 완료 146, 정상 수신 145, `bad=1`, `timeout=1`, CAN 오류 0 | 시험 중간부터 수신한 경우와 일치하지만 시작 순번 원본은 없음 |
| 재시험 | Node 1 RESET 유지 → Node 2 실행 → Node 1 RESET 해제 | 이후 Node 2가 3,000개 수신·응답 PASS. 시작 순서 불일치는 유력한 부분 수신 원인이나 최초 ACK 오류까지 같은 원인으로 단정하지 않음 |

부분 수신 로그에는 사용자가 `tx=`를 생략하고 `mask`를 `masx`로 적었다.
표에서는 출력 형식에 따라 해석했고 [전달 원문](evidence/user-reported-uart.txt)에는 그대로 보존했다.

## 6. 재현 절차

1. 두 보드의 `.ioc`와 `main.c`에서 CAN1 Normal을 확인하고 각각 빌드·다운로드한다.
2. 전원을 끈 상태에서 CANH/CANL, 공통 GND와 종단저항 약 60Ω을 확인한다.
3. Node 1 RESET을 누른 채 Node 2를 리셋하고 실행한다. 디버거 사용 시 F8로 Resume한다.
4. Node 2의 `NORMAL ECHO` 시작 로그 이후 2초 기다린 뒤 Node 1 RESET을 놓는다.
5. 시험 중에는 리셋·Suspend·중단점을 사용하지 않는다. 약 70초 후 결과를 기록한다.
6. 시작 로그의 노드명, 연결된 보드 및 COM 포트와 최종 로그를 함께 보존한다.

## 7. 남은 완료 조건

- [x] 양 노드 Loopback 정상 출력 확인(사용자 보고).
- [x] 연결된 버스 종단저항 약 60Ω 확인(사용자 측정).
- [x] Node 2 Normal 수신·에코 송신 3,000회, 오류 0 확인(사용자 제공 로그).
- [ ] Node 1의 실제 최종 PASS 로그 재확인 및 보존.
- [ ] 로직 애널라이저로 CAN 비트폭 2µs 확인 및 파형 보존.
- [ ] MCO 출력 주파수 실측 및 기록. Node 1의 SYSCLK/16 설정을 사용한다면 기대값은 3MHz이며 PA8의 기존 E-Stop 배선과 충돌하지 않게 준비한다.

계획서의 M2 전체 완료 판정은 위 미완료 항목을 확인한 뒤 갱신한다.
Bus-Off 강제 발생 시험과 복구, 장시간 전원 안정성, 모터 노이즈 환경, RTOS 및 최종
안전 제어 로직은 이번 성공 로그만으로 검증되었다고 보지 않는다.
