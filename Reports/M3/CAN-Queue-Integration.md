# M3-2 CAN RX 큐 이관 기록

작업일: 2026-11-09 (Asia/Seoul)

차량 F446RE의 CAN 수신 처리를 ISR → CMSIS 메시지 큐 → `canRxTask`로 이관했다. Node 1은 기존 M2 Normal 펌웨어를 사용한다. **M3-2 정상 통신·RTOS 통합 시험은 사용자 보고 기준 PASS다.** 양 노드 3,000프레임 왕복과 CAN 시험 후 RTOS 진단을 확인했다.

## 구현

- RX ISR은 한 번에 최대 3프레임을 꺼내 도착 시각과 함께 16슬롯 큐로 복사한다. `osMessageQueuePut()`의 timeout은 0이며, 실패 횟수를 별도 기록한다.
- AboveNormal 우선순위의 CAN 태스크가 검증·에코 송신·타임아웃·종료 판정을 담당한다. 큐 대기는 최대 10tick이며 프레임 도착 시 즉시 대기에서 풀린다.
- 큐는 커널 초기화 후 생성하고 CAN은 태스크에서 시작한다. 인터럽트가 아직 없는 큐를 사용하는 순서 문제를 피한다.
- M2와 동일한 ID/DLC/순번/페이로드를 사용한다. 길이가 정상인 손상 페이로드도 원문 그대로 에코한다.
- 수신/큐 삽입/처리/정상 검증/송신 등록/송신 완료가 모두 3,000회이고 오류와 잔여 큐 항목이 없어야 CAN PASS다.
- 첫 수신 전에는 계속 기다린다. 첫 수신 후 무수신 1초 이상, 전체 65초 이상, 큐 내 체류 1초 이상이면 실패로 종료한다. 마지막 수신 뒤 100ms를 기다려 송신 완료를 확인한다.
- 종료 시 CAN 알림과 세 IRQ를 끄고 결과를 고정한다. CAN 태스크는 suspend 상태로 남겨 스택을 확인하며 LED/진단 태스크는 계속 실행된다.
- UART 출력은 monitorTask만 수행한다. CAN 큐 최대 점유량, 최대 대기 시간, CAN 태스크 스택 여유를 추가했다.

- 실물 CAN 정상 통신, CAN 처리 후 세 태스크의 최소 스택 여유와 RTOS 오류 값은 사용자 전달 로그로 확인했다. 에이전트가 보드를 직접 조작하거나 UART를 수집한 결과는 아니다. queue overflow/Bus-Off 오류 주입은 미검증이다.
